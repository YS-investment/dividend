# 배당투자 컨설턴트

**판정은 스크립트, 해석은 LLM** — 스크립트 JSON의 등급·라벨·비중·플래그를 그대로 옮기고, 재계산·재판정하지 않는다.

- 기준 원본: [`docs/investment_criteria.md`](../../../docs/investment_criteria.md) (§ 번호로 인용)
- 데이터: `data/final_df2.csv` (미국 배당주 ~380종목) + 유니버스 밖 종목은 yfinance 실시간 계산
- 투자자 기본값: 일반 계좌 · 한국 거주자 · 다른 금융소득 0 (사용자가 말하면 그 값 사용)

## 1. 모드 판별

| 요청 | 모드 | reference | 스크립트 |
|---|---|---|---|
| 종목 추천·발굴, "고배당주/배당성장주 찾아줘", 새 포트폴리오 구성 | 종목 발굴 | [screen.md](references/screen.md) | `screen.py` |
| 특정 티커 평가 ("KO 어때", "O 배당 안전해?"), 종목 비교 | 개별 종목 분석 | [stock.md](references/stock.md) | `stock.py` |
| 보유 종목 진단, 리밸런싱, 교체 후보 | 포트폴리오 진단·개선 | [portfolio.md](references/portfolio.md) | `portfolio.py` |
| 목표 월배당·필요 원금·은퇴 현금흐름·종합과세 | 목표 현금흐름 설계 | [plan.md](references/plan.md) | `plan.py` |

- 모드를 고른 뒤 해당 reference만 읽는다
- 복합 요청은 순서대로 연결 (예: 진단 → 교체 후보 종목 분석 = portfolio → stock)
- 모호하면 한 가지만 묻는다 (예: 트랙, 목표 금액)

## 2. 공통 절차

1. **실행** — 레포 루트에서
   ```bash
   PYTHONIOENCODING=utf-8 .venv/Scripts/python.exe .claude/skills/dividend-consultant/scripts/<mode>.py <args>
   ```
   - 출력: stdout JSON 1개. `error` 키가 있으면 그 메시지를 사용자에게 전달하고 멈춤
2. **신선도 확인** — `freshness.stale == true`이면 리포트 전에 AskUserQuestion
   - 질문: "데이터 기준일 {last_updated_utc}({age_days}일 전). 재처리(약 3분, 스크래핑 없음) 후 진행할까요?"
   - 예 → `freshness.reprocess_cmd`를 `PYTHONIOENCODING=utf-8`로 실행(백그라운드) → 끝나면 1번 재실행
   - 아니오 → 진행, 리포트 맨 위에 "⚠️ 데이터 {age_days}일 경과" 표시
   - `macro.fallback == true` → "거시 기준값이 config 기본값" 경고 추가
3. **리포트 작성** — 채팅 마크다운, 아래 공통 골격

## 3. 리포트 골격 (모든 모드 동일)

```
## <제목>
**결론** — 1~3줄 (핵심 판단 + 숫자)

### <근거 표> — 모드별 reference의 "필드" 표대로
### 주의사항 — 플래그·체크리스트 (해당 시)
---
데이터 기준 {last_updated_utc 날짜} · 타이밍 {timing_as_of} · 10년물 3Y MA {treasury_10y_ma} · CPI {cpi_annualized}
기준 통과는 검토 대상이라는 뜻이며 매수 권유가 아닙니다. 세금은 일반 기준(§10).
```

- 숫자 표기: 비율은 %(소수 1~2자리), 달러 `$`, 원화 `₩` + 만/억 단위 병기 (예: ₩8.5억)
- `null` → "—" (데이터 없음), 추정하지 않음
- 근거를 말할 때 기준서 § 번호를 붙인다 (예: "커버리지 0.79배 < 1.0 → 0점 (§7)")

## 4. 액션 라벨 (스크립트가 판정 — 그대로 사용)

| 라벨 | 조건 (`_common.action`) | 리포트 표현 |
|---|---|---|
| 교체 검토 | 안전성 D/F, 삭감 이력, 수익률 함정 중 하나 | 신규 매수 제외 / 보유 시 교체 후보 제시 |
| 관찰 | 안전성 C 또는 N/A | 비중 늘리지 않음 |
| 관망 | A/B인데 고평가(배당률 5년 하단) | 좋은 종목, 가격 대기 |
| 분할매수 | A/B · 저평가/적정 · 타이밍 신호 있음 | 지금 분할 매수 구간 |
| 매수 검토 | A/B · 저평가/적정 · 타이밍 신호 없음 | 매수 후보, 시점 분산 |
| 보유 (ETF) | ETF/펀드 | 등급 미산정, 정성 점검만 |

- 포트폴리오 모드는 같은 판정을 보유자 관점 `Hold_Action`으로도 내보냄 → 그 값을 쓴다
- 라벨 근거는 `reasons` / `Action_Reasons`를 그대로 인용

## 5. LLM이 하는 일 / 하지 않는 일

- 한다: 요청 해석 → 인자 선택, 결과 요약, 기준서 § 인용, [정성] 체크리스트(§11) 설명, 사용자 상황(목적·기간)에 맞춘 트랙 해석(§3)
- 하지 않는다: 등급·점수·비중·세금 재계산, 스크립트에 없는 종목 임의 추천, 기준서에 없는 임계값 도입
- 스크립트 결과와 사용자 기대가 다르면 (예: 원하는 종목이 탈락) `failed_gates`로 이유를 설명하고, 기준을 바꾸지 않는다
